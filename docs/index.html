🌱 Why I built this

Every good project starts with a real itch.

I had a huge, overflowing Gmail — tens of thousands of messages, most of it job alerts, promotions, and bank notifications I never needed. I wanted to organize what matters and clear out what doesn't to reclaim space, but doing that by hand across 20,000+ emails is impossible — and I didn't trust a bot to silently touch my mailbox.

So I built Inbox Pilot: it does the heavy lifting, while I approve every change.

It reviews mail by sender + category, so one click handles thousands at once. It learns from my decisions so it keeps getting faster. And in v1 it's strictly non-destructive — labels only, never deletes. The "declutter and delete to free space" part is on the roadmap as a human-approved step, never an automatic one.

✨ What it does

Powerful automation, with a human firmly in the loop.

🧲

Metadata-only ingest

Reads sender, subject, date, and snippet. It never reads or stores the body of your emails.

🏷️

Smart labels, 3 ways

Deterministic rules → a cheap batched LLM → NEEDS_REVIEW. It refuses to guess when unsure.

🧑‍✈️

You're the pilot

Nothing is applied to Gmail until you approve it. Flip a LIVE ⇄ DRY-RUN toggle anytime.

📦

Bulk review at scale

Approve a whole sender × label group in one click. Expand to inspect, or relabel first.

🧠

Learns as you go

Every approval becomes a rule — that sender is classified for free next time.

🛡️

Safe by design

Label-only, reversible, fully audited, resilient to Gmail rate limits.

🛠️ How it works

You approve patterns, not emails — 20,000 messages come from only a few hundred senders.

1

Ingest

Pulls mailbox metadata in fast, resumable batches — rate-limit proof.

2

Classify

Rules → cheap LLM → needs-review, into a fixed, editable taxonomy.

3

Review

Bulk-approve by sender × label on a clean dashboard. One click, thousands sorted.

4

Apply

Approved labels land in Gmail and are logged. It learns for next time.

🚀 Quickstart

Python 3.13 · Node 18+ · a Google OAuth credentials.json.

# install
cd backend && python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
cd ../frontend && npm install

# (recommended) enable the cheap LLM classifier
cp backend/.env.example backend/.env    # then add ANTHROPIC_API_KEY

# run both, then open http://localhost:5173
uvicorn app.api.main:app --reload       # from backend/
npm run dev                              # from frontend/

In VS Code: Run and Debug → “▶ Run App (backend + frontend)” starts both at once.
