The problem

Fully manual is impossible. Fully automatic isn't safe.

I had a huge, overflowing Gmail and wanted to organize what matters and clear out what doesn't to reclaim space. Doing it by hand across tens of thousands of messages is impractical — but handing a bot the keys to silently relabel or delete my mail is exactly what I didn't want.

The real need: automation that does the work, with a human approving every change.

How we solve it

You approve patterns, not emails

20,000 emails come from only a few hundred senders — so you make dozens of decisions, not twenty thousand.

1

Ingest

Pulls mailbox metadata (never the body) in fast, resumable batches — rate-limit proof.

2

Classify

Sorts each email into a tidy category: rules first, then a cheap AI, then “ask me”.

3

Review

Approve a whole sender × label group in one click. Expand to inspect; relabel if needed.

4

Apply

Approved labels land in Gmail and are logged. It learns your choices for next time.

Under the hood

The technical view

Ingest once into a local store; classify, review and apply off that copy. Gmail is touched only to read metadata and to apply approved labels.

Actual data flow. The dashed violet arrow is the learning loop — each approval becomes a rule that classifies that sender automatically next time.

3-state classifier (never guesses)

learned → rules (whole-word, sender-domain weighted) → LLM (Claude Haiku, batched ~20/call) → NEEDS_REVIEW. Taxonomy is editable YAML; labels are hierarchical.

Human-in-the-loop workflow

A LangGraph graph pauses at an approval step via interrupt(); approvals & apply are also exposed directly over the API so review survives refreshes and restarts.

Resilient full-inbox crawl

Batched Gmail requests (~50/round-trip), retries on 403/429/5xx with backoff, skips bad items, resumes where it left off — runs in the background.

Safe, auditable data model

SQLite tables for metadata, proposals, learned rules and an append-only audit log. Scope is gmail.modify — it can label but cannot delete.
